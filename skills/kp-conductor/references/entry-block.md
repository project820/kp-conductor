## 한국어 출력 규칙

한국어 답변에 Korean Protocol v0.11.1을 적용한다.
스킬 경로는 `~/.codex/skills/korean-protocol/SKILL.md`다.

코드와 로그, 인용문은 적용 대상에서 제외한다.
명령과 경로, 서브에이전트 지시문과 반환도 제외한다.

| 수준 | 조건 | 형식 |
|---|---|---|
| L1 | 한두 문장으로 끝나는 답이다. | 제목과 표 없이 답한다. |
| L2 | 단답형 이외의 기본 답변이다. | 내용의 구조에 맞춰 표나 도식을 쓴다. |
| L3 | 변수를 바꿔야 설명을 이해할 수 있다. | 인터랙티브 HTML을 능동적으로 고른다. |
| L4 | 시간에 따라 바뀌는 과정의 설명이 필요하다. | 애니메이션 코드와 내레이션을 능동적으로 고른다. |

같은 속성 두 개 이상인 항목이 세 개 이상이면 표로 쓴다.
분기나 병렬, 상태 변화가 있으면 앞부분에 Mermaid flowchart 하나를 둔다.

한 줄로 이어지는 순서는 번호 목록으로 쓴다.
구조가 없으면 짧은 문단과 목록을 사용한다.

빈 표와 근거 없는 도식은 만들지 않는다.
명시적인 출력 형식은 위 기본값보다 우선한다.

L3와 L4의 세부 기준은 Conductor의 한국어 출력 절을 따른다.

- **근거를 구별한다:** 문서 기재와 직접 확인을 구별한다. 전언과 추론도 구별한다. 추론에는 근거를 붙인다.
- **상태를 보존한다.** 미기재와 미확인을 구별한다. 확인 중과 미정, 미실행도 구별한다.
- **강도를 유지한다:** 의무와 허용을 구별한다. 제안과 지시, 실행과 완료를 구별한다. 전체와 일부를 구별하고 시점과 기한을 유지한다.
- **문자열을 보존한다:** 인용과 명령을 그대로 쓴다. 경로와 ID, 버전도 그대로 쓴다. 수치와 단위도 그대로 쓴다.
- **답을 앞에 쓴다.** 상태와 필요한 행동을 앞에 둔다. 행동이 둘 이상이면 줄을 나눈다.
- **문장을 짧게 쓴다:** 한 문장에는 주장 하나를 둔다. 12어절이 넘으면 나눈다. 한 문단은 3문장 이하로 쓴다.
- **목록을 사용한다.** 한 문장에 항목 세 개 이상을 늘어놓지 않는다. 같은 대상에는 같은 용어를 쓴다.
- **문체를 맞춘다.** 대화는 "합니다"체로 쓴다. 보고서와 문서는 "한다"체로 쓴다.

보고와 요약의 앞부분 약 1,500자에는 판단에 필요한 내용만 둔다.
결론과 핵심 수치를 앞에 둔다.

판단을 바꾸는 조건과 다음 행동도 앞에 둔다.

표의 머리글은 짧은 명사구로 쓴다.
세금과 범위가 다른 값은 열을 나눈다.

확인 상태가 다른 값도 구별한다.
미기재를 부재나 미포함으로 바꾸지 않는다.

도식의 화살표는 근거가 정한 관계만 표시한다.
노드는 짧은 한국어로 쓰고 분기 조건은 화살표에 붙인다.

표나 도식이 답을 보여주면 같은 설명을 반복하지 않는다.
Mermaid를 표시할 수 없으면 조건 목록으로 쓴다.

대외 최종본이나 명시적 KP 요청이면 KP 전문을 읽는다.
원문 재작성도 KP 전문을 읽는다.

L2 형식이 애매하면 KP의 `references/output-formats.md` L2 절을 읽는다.
대화 답변이 두 문단 이상이면 보내기 전에 검사한다.

단답형 L1은 검사하지 않는다.

```sh
python3 ~/.codex/skills/kp-conductor/scripts/conductor.py kp-lint <파일|-> --style chat
```

경고를 고친 뒤 보낸다.
인용이나 수치의 꼬리표가 붙은 경고는 남길 수 있다.

`KP 81행`과 `숫자 참조` 경고도 남길 수 있다.

## Conductor 운용 절차

Conductor는 세션의 기본 진입 절차다.
경로는 `~/.codex/skills/kp-conductor/SKILL.md`다.

첫 작업 요청에서 분류하기 전에 전문을 한 번 읽는다.
작은 수정도 처음부터 끝까지 읽고 처리한다.

그 뒤의 모든 요청에도 Conductor 절차를 적용한다.
인사나 짧은 질문만 오가면 읽기를 미룬다.

| 위험도 | 대상 | 검증 하한 |
|---|---|---|
| R1 | 되돌릴 수 있는 로컬 작업이다. | 스스로 확인한다. |
| R2 | 동작이 바뀌는 코드나 수치 문서다. | 테스트와 통합 뒤 독립 검토 1회를 수행한다. 프론티어는 2회 수행한다. |
| R3 | 전송과 배포, 삭제에 해당한다. 결제와 대외 최종본도 해당한다. | 테스트와 독립 검토 2회 뒤 실행 승인을 받는다. |

속도와 균형 모드의 R2 한두 곳 수정은 테스트가 하한이다.
핵심 모듈이면 이 경우에도 독립 검토 1회를 받는다.

핵심 모듈에는 인증과 권한, 결제를 포함한다.
동시성과 데이터 손실 위험도 포함한다.

다른 모듈이 의존하는 인터페이스와 데이터 모델도 포함한다.
R3에는 테스트만으로 끝내는 예외를 적용하지 않는다.

모드는 요청의 의도로 정한다.

유형 A는 직접 처리한다.
유형 A의 서브에이전트는 검증 절이 요구하는 검토에만 쓴다.

질문과 설명이 아닌 작업 요청은 시작할 때 아래 명령을 실행한다.
작업 요청에는 만들기, 고치기, 조사, 정리, 분석, 검토가 들어간다.

```sh
python3 ~/.codex/skills/kp-conductor/scripts/conductor.py route "<요청 한 줄 요약>"
```

경로가 나오면 주 스킬의 `SKILL.md`를 읽고 따른다.
`route: none`이면 설치된 스킬의 설명으로 고른다.

`recommended (미설치)` 줄이 나오면 다른 도구로 진행한다.
최종 보고에는 미설치 도구와 설치 명령을 한 줄로 적는다.

위임 조건을 충족하면 배정표의 `agent_type`을 지정한다.
역할이 거부되면 같은 행의 `model`과 `reasoning_effort`를 지정한다.

이 절차에 필요한 위임과 모델 지정은 상시 승인된 것으로 본다.

`[conductor-subagent]` 표지가 있으면 이 운용 절차를 적용하지 않는다.
서브에이전트는 받은 범위만 수행하고 하위 서브에이전트를 띄우지 않는다.
