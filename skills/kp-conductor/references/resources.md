# 분야와 자원

역할의 모델·강도는 `cx status`의 roles 줄을 따른다. 개인 배정은 `<state>/local/roles.json`, 모델 특성은 `<state>/local/notes.md`에 둔다. 개인 설정이 없으면 기본 예시를 쓴다.

## 분야별 배정

| 분야 | 본작업 | 교차 검토 | 가벼운 작업 |
|---|---|---|---|
| 재무·회계 | `cx-hard` | `cx-review` | 수치 정리는 직접 처리한다 |
| 전략·운영 | `cx-hard` | `cx-review` | 전략 초안은 직접 쓸 수 있다 |
| 법률 | `cx-hard` | `cx-review` | 짧은 판단은 직접 처리하고 advisor를 붙인다 |
| 엔지니어링 | `cx-build`, 난제 분석은 `cx-hard` | `cx-review` | 기계적 수정은 `cx-build-lite`를 쓴다 |
| 경제 | `cx-hard` | `cx-review` | 짧은 판단은 직접 처리하고 advisor를 붙인다 |

수치가 들어가는 재무 산출물은 작성자와 다른 공급사 모델이 반드시 한 번 검토한다. 참여 모델 제외와 한도 제한은 SKILL.md의 검증 절을 따른다.

## 스킬 지도

`cx route "<요청>"`으로 경로와 주 스킬을 찾는다. 지도는 `<state>/local/routing.json`, 없으면 패키지 [routing.json](routing.json)이다. 출력된 설치 경로의 SKILL.md를 읽는다.

Conductor는 역할과 검증 강도를 정한다. 작업 방법은 해당 스킬이 정한다. 기본 틀에 전용 스킬이 없는 범주는 설치 목록에서 고른다.

기본 틀은 Codex 기본 플러그인과 공개 원본이 있는 권장 스킬을 담는다. 개인 도구와 연결 서비스는 온보딩으로 개인 지도에 넣는다. 개인 사용 통계는 `<state>/`에만 기록한다.

## 분류·채점 도구

설치된 분류·채점 도구는 아래 작업에 쓸 수 있다.

- 테스트가 없는 경쟁 산출물을 루브릭으로 채점한다.
- 회고의 요청 표본을 유형별로 묶어 분류한다.
- 여러 완료 조건을 한 번에 판정한다.

매 요청 분류는 요청을 읽은 오케스트레이터가 직접 한다. 도구의 인증·비용 규칙을 따르며, API 답만으로 최종 인수하지 않는다. 같은 산출물의 요구 충족과 근거는 별도로 확인한다.

## 개인화 근거

회고는 직접 호출과 스킬 읽기를 함께 본다. 연결된 도구 호출과 성과 기록도 본다. 자주 쓰지만 지도에 없는 스킬을 개인 경로 후보로 삼는다.

적용 권한과 최소 기록 수는 [retrospective.md](retrospective.md)를 따른다.

## 모드 표현

| 표현 | 모드 |
|---|---|
| 최고 품질로, 제대로 해줘, 중요한 거야, 꼼꼼하게, 대외용 최종본 | 프론티어로 정한다 |
| 빨리, 급해, 빠르게, 초안만 | 속도로 정한다 |
| 아껴서 | 균형과 절약 상태를 켠다 |
| 일단 기억해 둬 | 속도 지정으로 해석하지 않는다 |
| 상용 서비스만큼, 디자인 퀄리티, 예쁘게 | 화면일 때 비주얼 트랙만 붙인다 |

## 판단 자리

| 자리 | 판단 역할 | 오케스트레이터 |
|---|---|---|
| 유형 E | cx-hard가 본분석과 결론 초안을 쓴다 | 자료 수집·사실 확인·통합·저장을 한다 |
| 판단 문서 검토 | cx-hard가 검토한다 | 지적을 반영한다 |
| R2 이상 구현 상담 | advisor가 상담한다 | 선택하고 구현을 배정한다 |
| 큰 비주얼 변경 | cx-hard가 정보 구조·시각 방향·상태 명세를 쓴다 | 구현하고 통합한다 |
| 문서·전략 경쟁 | cx-hard가 후보 하나를 낸다 | 후보를 저장하고 cx-review에 판정을 맡긴다 |
| 코드 경쟁 판정 | cx-hard가 비교한다. 80% 이상으로 제한되면 cx-hard-alt1이 맡는다 | 판정을 반영한다 |

승격 마지막 분석과 프로필 평가는 cx-hard가 맡는다. 외부 스킬 평가는 cx-council이 맡는다.

## 판단 지시문

parallel.md의 작업자 지시문에 아래 항목을 더한다. 대체 역할에도 같은 지시문을 준다.

1. 배경은 작업 주체와 결과 용도를 두세 문장으로 적는다.
2. 사용자 승인 범위를 적는다. 실행과 전송을 금지하고 파일 수정도 금지한다.
3. 판단 자료를 붙이거나 읽을 경로를 준다.
4. 분석이나 초안 작성 또는 검토 중 맡길 일을 한 문장으로 적는다. 압박 문구와 역할극은 넣지 않는다.
5. 반환 구획은 아래 네 개로 나눈다.
   - 결론을 받는다.
   - 근거를 받는다.
   - 불확실한 점을 받는다.
   - 권고를 받는다.

## 기록 값

| 값 | 뜻 |
|---|---|
| skill-fit good | 지침이 결과에 도움이 됐다 |
| skill-fit poor | 스킬이 부적합했거나 그 때문에 재작업했다 |
| skill-fit none | 결과에 차이가 없었다 |
| outcome refused | 내용 거절이다 |
| outcome error | 인증·과부하·시간 초과·빈 응답 오류다 |

## 검토 참여

| 참여 활동 | 독립 검토 자격 |
|---|---|
| 작성 | 제외한다 |
| 공동 분석 | 제외한다 |
| 승격 원인 분석·수정안 제시 | 제외한다 |

## KP 검토 항목

- 근거와 확인 상태를 구별하는지 검토한다.
- 의무 강도를 보존하는지 검토한다.
- 시점과 수량을 보존하는지 검토한다.
- 인용과 수치를 글자 그대로 보존하는지 검토한다.
- 경로를 글자 그대로 보존하는지 검토한다.
- 출력 수준이 적절한지 검토한다.
- 표와 도식이 근거 없는 관계를 만드는지 검토한다.

## 도구 선택

1. 경로 최대 3개에서 중심 작업을 주 경로로 고른다. 나머지는 보조 단계로 배정한다.
2. 직접 처리하면 주 스킬의 SKILL.md를 읽는다. 위임하면 스킬 이름·경로와 역할을 준다.
3. 경로 위험도를 하한으로 쓴다. 같은 일의 스킬은 지도 순서를 따른다.
4. allowed false이면 역할 없이 띄우고 보고한다.
5. route: none이나 빈 스킬 목록이면 설치된 스킬 설명으로 고른다. 맞는 스킬이 없으면 스킬 없이 진행한다.
6. 꺼진 스킬과 `settings.json`의 `banned_skills`에 있는 스킬은 쓰지 않는다.
7. 지시문에는 요약·근거 경로나 결과 파일 경로로 반환 형식을 정한다.

## 프로젝트 프로필

프로필이 없으면 checkpoint가 균형·R2(`by auto`)로 만든다. 요청 중에는 별도로 평가하지 않는다. 회고가 자동 프로필을 `cx-hard` 하나에 모아 평가한다.

1. 프로젝트별 README와 AGENTS.md에 파일 구성을 더해 10줄 안으로 요약한다.
2. 아래 항목과 근거 한 줄을 받는다.
   - 기본 모드를 받는다.
   - 기본 위험도를 받는다.
   - 분야를 받는다.
   - 검증 명령을 받는다.
3. 통상 작업을 끝낼 최소 자원으로 평가한다.
4. 회고의 `retro.apply`와 변경 권한을 먼저 확인한다.
   - `propose`이면 평가 결과를 `<state>/proposals/<날짜>.md`에만 적는다. `cx profile set`은 실행하지 않는다.
   - `notify`이면 평가 결과를 알리고 `cx profile set ... --by judge`로 기록한다.
