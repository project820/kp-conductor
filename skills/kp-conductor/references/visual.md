# 비주얼 트랙

사용자가 볼 화면이 산출물일 때 모드 위에 붙이는 절차다. 모드는 반복 횟수와 검토 깊이를 정하고, 이 문서는 무엇을 확인해야 끝나는지를 정한다. 브라우저 작업은 Codex 내장 브라우저로 한다.

## 절차

| 단계 | 하는 일 | 완료 기준 |
|---|---|---|
| 1. 목표 | 사용자, 핵심 과업, 변경 범위, 보존할 요소를 정하고 현재 화면을 찍는다 | 대상 화면과 상태가 특정된다 |
| 2. 레퍼런스 | `stylegallery`와 공개 자료에서 참고 화면 3개 이상을 모은다. 채택·제외 이유를 적는다. ui-unslop 경로는 감사 목록과 방향 5줄로 대신한다 | 주요 변경마다 근거 화면이 있다 |
| 3. 디자인 시스템 | 기존 색·간격·타이포·컴포넌트를 재사용한다. 없으면 최소 토큰부터 정한다 | 같은 토큰과 컴포넌트를 쓰고, 예외에는 이유가 있다 |
| 4. 상태 | 정상, 로딩, 빈 결과, 오류, 긴 내용 중 변경에 관련된 상태를 만든다 | 핵심 과업이 끝나고 오류에서 회복된다 |
| 5. 시각 반복 | 내장 브라우저로 찍고, 고치고, 같은 조건으로 다시 찍는다 | 잘림·겹침·누락·위계 혼선이 없고 전후 스크린샷이 남는다 |
| 6. 반응형 | 320, 390, 768, 1440 CSS px와 실제 레이아웃 전환 경계를 본다 | 320px에서 정보 손실과 가로 스크롤이 없다 |
| 7. 접근성 | WCAG 2.2 AA 기준 axe 검사, 키보드, 포커스, 이름, 오류 안내 | 확정 위반 0건, axe의 incomplete는 직접 판정, 키보드로 과업이 끝난다 |
| 8. 성능 | 같은 빌드·장치·네트워크 조건으로 Lighthouse를 여러 번 재고 중앙값을 적는다 | 새 화면은 성능 90 이상, 기존 제품은 미리 정한 예산 |
| 9. 휴리스틱 | NN/g 10원칙과 심각도 척도(0~4)로 평가한다 | 심각도 3·4 미해결 0건, 경미한 문제는 영향과 남긴 이유를 적는다 |

- **반복 횟수:** 5~9단계를 한 번 도는 것이 1회다. 지적 수가 줄지 않으면 멈추고 미완료로 보고한다. 횟수를 다 써도 완료 기준이 남으면 멈추고 미완료로 보고한다.
- **실사용 지표:** Lighthouse는 페이지 로드 검사라 INP를 재지 않는다. 실사용 데이터가 있을 때만 아래 Core Web Vitals 기준을 판정한다. 데이터가 없으면 "미측정"으로 적는다.
- **판정의 범위:** 전체 WCAG 적합성이나 실제 사용자 만족을 뜻하지 않는다. "검사 통과"는 검사한 화면과 상태에 대한 결과다.

| 모드 | 반복 |
|---|---:|
| 속도 | 1회 |
| 균형 | 2회 |
| 프론티어 | 3회 |

| 실사용 지표 | 기준 | 판정 범위 |
|---|---|---|
| LCP | ≤2.5초 | 75백분위로 판정한다 |
| INP | ≤200ms | 75백분위로 판정한다 |
| CLS | ≤0.1 | 75백분위로 판정한다 |

## 속도 모드

- 속도 모드의 1회는 5·6단계와 아래 "유지한다" 항목이다. 7~9단계는 "유지한다" 항목으로 대신한다.
- **유지 범위:** 아래 검사를 유지한다.
  - 변경 화면의 좁은 폭(320px)을 확인한다.
  - 키보드로 과업을 확인한다.
  - 핵심 흐름을 확인한다.
  - 오류 상태를 확인한다.
- **축소 범위:** 아래 작업을 줄인다.
  - 레퍼런스 재검색은 이전 근거를 재사용한다.
  - 전면 시각 회귀를 줄인다.
  - 대안 수를 줄인다.
  - 새 이미지 생성을 줄인다.
- 권한, 결제, 데이터 손실이 걸린 화면은 속도 모드에서도 검증을 줄이지 않는다.

## 역할 배정

| 변경 크기 | 설계 | 구현 | 화면 검토 |
|---|---|---|---|
| 큰 변경(새 화면, 정보 구조 변경) | `cx-hard`이 정보 구조, 시각 방향, 상태 명세를 쓴다 | 오케스트레이터가 대표 화면을 구현·통합하고, 경계가 정해진 반복 컴포넌트는 `cx-build` | `cx-review`. 2회째는 `cx-hard`(명세만 썼으므로 구현의 참여 모델이 아니다) |
| 작은 수정(한 화면) | 오케스트레이터 | 오케스트레이터 | `cx-review` |

- **화면 검토 자료:** 코드와 함께 아래 자료를 준다.
  - 전후 스크린샷 경로를 준다.
  - 재현 경로를 준다.
  - axe·Lighthouse 검사 결과를 준다.
- **화면 검토 항목:** 아래 항목을 검토한다.
  - 위계를 검토한다.
  - 간격을 검토한다.
  - 타이포를 검토한다.
  - 상태를 검토한다.
  - 반응형을 검토한다.
  - 대비를 검토한다.
  - 기존 디자인 시스템 일치를 검토한다.
  - 절차 표의 완료 기준을 검토한다.
- **독립성:** 오케스트레이터의 화면 확인은 자체 점검이다. 검토자에게 스크린샷을 직접 읽게 한다. 읽지 못하면 완료 보고에 적고 독립 화면 검토는 미충족으로 둔다.
- **선정:** SKILL.md의 참여 모델 제외와 다른 공급사 우선 규칙을 따른다. 명세만 쓴 모델은 구현 참여 모델로 보지 않는다.
- **재평가:** 로컬 기록 10건이 쌓이면 회고가 역할 배정 조정안을 만든다.

## 기록

체크포인트를 `--visual`로 열고, 끝낼 때 `--visual-iterations <n> --visual-defects <심각도 3·4 미해결 수> --visual-accepted yes|no|unknown`을 적는다. 완료 보고에 전후 스크린샷 경로를 붙인다.
