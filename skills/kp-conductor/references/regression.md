# 시범 요청

아래 표는 시범 요청의 기대 동작을 제시한다.

온보딩 9단계의 마무리 확인에 실행한다. 규칙이나 역할 배정 또는 경로를 바꾼 뒤에도 실행한다. 별도 시험 폴더의 새 세션에서 처리 방식과 기록을 확인한다.

## 실행

1. 작은 README와 서로 독립된 구현 대상 두 개를 시험 폴더에 준비한다. 탐색용 파일은 10개 이상 준비한다.
2. 요청마다 `codex exec --ephemeral --json '<요청>' < /dev/null > events.jsonl`로 새 세션을 실행한다. 기록을 보존하려면 요청별 결과 폴더를 나눈다.
3. 포그라운드에서 실행한다. 표준 입력을 `/dev/null`로 막아 입력 대기를 방지한다.
4. 아래 기대 동작과 실행 기록을 비교한다. 실제 통과·실패와 미확인을 구별해 적는다.

| 시범 요청 | 기대 분류 | 기대 동작 |
|---|---|---|
| README.md 첫 줄을 알려줘 | A | 오케스트레이터가 직접 읽는다. 서브에이전트를 띄우지 않는다 |
| 이 폴더의 파일 12개를 각각 읽고 역할을 표로 정리해줘 | B | 목록을 구역으로 나눠 `cx-explore` 2~3개에 맡긴다. 파일별 근거 경로를 받는다 |
| 독립된 두 모듈의 함수를 구현하고 각각 테스트해줘 | C·R2 | 파일 소유권을 나눠 `cx-build`를 병렬 배정한다. 통합 후 테스트와 독립 검토를 수행한다 |
| 제공 자료로 두 사업 전략의 재무 위험을 분석해줘 | E·R2 | `cx-hard`가 본분석하고 오케스트레이터가 통합한다. 추론 프론티어는 관련 한도 키가 모두 on일 때만 적용한다 |
| 이 화면의 AI 티를 없애고 사용성을 개선해줘 | C·R2 | `cx route`가 `ui-unslop`을 제안한다. unslop을 읽고 비주얼 트랙을 적용한다 |

역할이 거부되면 roles 줄의 모델·강도를 직접 지정한다. 실제 모델 지정도 거부되면 상속 사실을 보고한다. 스킬이 미설치면 설치 완료로 쓰지 않고 누락을 보고한다.

## 확인할 기록

- `events.jsonl`의 `spawn_agent` 호출과 지시문에서 역할과 소유 파일을 확인한다. 반환 형식도 확인한다.
- `ocx logs --limit 300 --json`에서 같은 conversationId의 requestedModel과 requestedEffort를 확인한다.
- `<state>/receipts.jsonl`과 `<state>/runs/`에서 위임 실패와 체크포인트를 확인한다.
- 한국어 출력의 수준과 표·도식이 요청 구조에 맞는지 확인한다.

읽기 전용 세션에서 상태 폴더 쓰기가 막히면 기록 확인은 미충족이다. 기록까지 검증하려면 상태 폴더에 쓰기가 허용된 시험 세션을 사용한다.

엔진 분류·검증 하한의 결함은 upstream 제안으로 남긴다. 개인 경로·배정 결함은 백업 후 개인 설정을 수정하고 verify를 실행한다.
